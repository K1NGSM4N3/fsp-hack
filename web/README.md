# web - фронтенд "ФСП Таланты"

Next.js 16 (App Router) + TypeScript strict, Tailwind CSS 4, TanStack Query, react-hook-form + zod, GSAP + Lenis
для анимаций публичного сайта. Node.js >= 20.9. Команды - `package.json`, переменные окружения - `docs/guide.md`,
раздел 3.11, какие страницы и что на них - README, раздел 1.3. Здесь - решения, которые не видно из списка файлов.

## Рендеринг

- Публичный сайт (`src/app/(public)`) рендерится на сервере; кабинеты (`/candidate/*`, `/employer/*`, `/admin/*`) -
  клиентские страницы с TanStack Query.
- `/vacancies` пересобирается раз в минуту (ISR) с первой страницей вакансий в HTML, `/vacancies/[id]` рендерится на
  сервере с вакансией внутри (неизвестный id - настоящий 404). Браузер стартует с этими данными (`initialData`) и дальше
  работает через API. Пока собирается образ, API недоступен: та сборка `/vacancies` без списка, его загрузит браузер.
- `src/app/providers.tsx` (QueryClient и тосты) подключается только там, где есть запросы к API: кабинеты, вход,
  вакансии, страница представителя. Маркетинговые страницы его не загружают.
- В кабинетах соискателя и компании свои `error.tsx` и `loading.tsx`: оболочка и меню остаются, заменяется только
  раздел.
- `src/proxy.ts` только перенаправляет на `/login` без cookie `fsp_session`; права проверяет API.

## Клиент API и сессия

- Типы ответов - только из OpenAPI бэкенда (`src/api/schema.d.ts`, `make gen-api`); мок-API типизирован теми же
  схемами, поэтому расхождение с бэкендом ловит `tsc`.
- `src/api/client.ts` - своя обёртка над `fetch`. Обновление сессии одно на все запросы: до запроса, если cookie
  `fsp_at_exp` говорит, что access-токен истёк (`src/api/session-hint.ts`), иначе после 401. problem+json
  превращается в `ApiError`. Непрочитанные тела ответов отменяются: иначе ответ `no-store` держит соединение в Chrome.
- Шапка публичного сайта проверяет сессию без клиента API (`src/features/auth/session.ts`): сначала `/session`
  (Next читает httpOnly-маркер `fsp_session`), и только при входе - `/api/v1/me`. Без сессии в консоли нет ни
  одного 401.
- Страницы кабинетов зовут API через хуки `src/features/*/hooks.ts`; исключения - видеозапись теста и скачивание
  PDF-профиля, они вызывают `src/api/endpoints.ts` напрямую.

## Формы

- Длинные формы (вакансия, потребность): пронумерованные разделы, справа - предпросмотр или сводка с готовностью,
  внизу - плавающая панель действий `FormActions`, которая перечисляет, что осталось проверить.
- Ошибки показываются у поля (`aria-describedby`, `role="alert"`) после первой попытки отправки и пропадают по мере
  исправления; `focusFirstError` переводит фокус к первому полю с ошибкой.
- Форма новой вакансии и приглашения отправляет один `Idempotency-Key` на всё время жизни формы: двойной клик не
  создаёт дубль.
- Растущие списки грузятся страницами по курсору кнопкой "Показать ещё" (`LoadMore`): число показанного - в
  `aria-live`, после последней страницы фокус переходит на "Показаны все".

## Мок-режим

`NEXT_PUBLIC_USE_MOCKS=1` в `.env.local`. Каждая функция `src/api/endpoints.ts` тогда уходит в `src/mocks/handlers.ts`
(модуль загружается лениво), состояние живёт в `localStorage`. Сквозной сценарий работает целиком: регистрация ->
подтверждение email ("демо-почта" на экране) -> профиль -> опрос -> адаптивный тест -> категория -> приглашение ->
контакты.

- Демо-аккаунты `candidate@demo.fsp` и `employer@demo.fsp`, пароль `demo12345` - как в сиде бэкенда.
- ФСП ID: `FSP-000001`, `FSP-000003`, `FSP-000006`, `FSP-000010` (без достижений), как в `crates/fsp-mock`;
  `FSP-000002` уже привязан к демо-кандидату. Ввод номера вручную есть только в мок-режиме.
- "Сбросить демо-данные" - в боковой панели кабинета.
- Тест короче боевого: 6-12 заданий вместо 8-20. Вместо PDF-профиля открывается страница для печати
  `/candidate/profile/print`. Кабинет модератора в мок-режиме недоступен.

## Доступность

Цель - 100 в Lighthouse Accessibility на публичных страницах и ноль нарушений axe в кабинетах.

- **Контраст через токены.** Серые `ink-subtle`, `ink-faint`, `night-faint` подобраны так, что текст ими проходит
  WCAG AA (4,5:1) на всех фонах, где используется. Кольцо фокуса на тёмных фонах светлое (`primary-300`).
- **Ссылки в тексте** - утилита `link-inline`: цвет плюс подчёркивание (одного цвета мало, WCAG 1.4.1).
- **Анимации не прячут контент.** Появления меняют `opacity`, а не `visibility`: текст ниже первого экрана остаётся в
  дереве доступности и в порядке табуляции. У разбитого SplitText текста есть доступная копия (`sr-only` или
  контурный слой), а сам он `aria-hidden`. Декоративные макеты с полупрозрачным текстом - `aria-hidden` и `inert`.
- **Кабинеты:** шапка - `header` с хлебными крошками в `nav`, мобильное меню - нативный `<dialog>` (ловушка фокуса,
  Esc, возврат фокуса), у вкладок `Tabs` всегда есть панель, тосты объявляются через `aria-live`. Фильтры поиска на
  телефоне свёрнуты за кнопкой с `aria-expanded`, Esc закрывает и возвращает фокус.

## SEO и ИИ-поиск

- `app/robots.txt/route.ts` явно разрешает публичные страницы поисковикам и ИИ-краулерам (Googlebot, YandexBot,
  GPTBot, ClaudeBot, PerplexityBot и другим), закрывает кабинеты, `/admin`, `/guardian`, `/login`, `/register`,
  `/api/`; `Clean-param` для utm-меток (Яндекс).
- `app/sitemap.ts` - публичные страницы из `PUBLIC_PAGES` (`src/lib/site.ts`) и опубликованные вакансии (до 100,
  рендерится по запросу). Кабинеты и `/verify-email` - `noindex`.
- Open Graph: `opengraph-image.tsx` у каждой публичной страницы и у вакансии (название, компания, вилка). Satori не
  читает WOFF2 и вариативные шрифты, поэтому Onest и JetBrains Mono лежат статическими TTF в `assets/og`; для вакансий
  они попадают в standalone-сборку через `outputFileTracingIncludes`.
- JSON-LD рендерится на сервере: Organization и WebSite везде, BreadcrumbList на внутренних страницах, ItemList на
  `/vacancies`, JobPosting на вакансии (вилка в RUB за месяц, `TELECOMMUTE` для удалёнки, город для офиса и гибрида,
  `directApply`). Тип занятости не размечается: у вакансий есть формат работы, но нет полной или частичной занятости.
- `/llms.txt` (по llmstxt.org) - что это за платформа и ссылки на страницы. `/llms-full.txt` - факты о продукте плюс
  текст всех публичных страниц, извлечённый из их собственного HTML, и список вакансий. Страницы запрашиваются у этого
  же процесса по `127.0.0.1:$PORT` и кешируются на 10 минут, поэтому текст не расходится с сайтом.
- `npm run check:seo [адрес]` запрашивает сайт как GPTBot без JavaScript и проверяет robots, sitemap, llms-файлы,
  один `h1`, `lang`, canonical, `<main>` и JSON-LD на каждой странице.

## Анимации

Только на публичном сайте; разметка без JS полностью читаема, первый экран от анимаций не зависит. Код - в
`src/components/motion/`.

- **Ленивый GSAP.** `useMotion` загружает GSAP отдельным чанком после гидратации, а плагины конкретного блока -
  только на тех страницах, где они нужны. Компоненты активируются по одному за задачу (`setTimeout(0)`), первыми -
  герой и шапка, поэтому на телефоне после гидратации нет одной длинной задачи. Всё созданное живёт в
  `gsap.context` компонента и откатывается при размонтировании.
- **Два профиля** (медиазапросы в `config.ts`). Десктоп (мышь и ширина >= 1024 px): SplitText в заголовках, появления
  по варианту страницы, пины и scrub, параллакс, Lenis, интерактивный граф-канвас. Телефоны и планшеты: одноразовые
  появления только через transform и opacity, вертикальные списки и нативные snap-ленты вместо пинов, нативный
  скролл без Lenis, редкий граф одним кадром.
- **MotionRoot.** Серверная страница размечает элементы data-атрибутами (`data-hero`, `data-split`, `data-reveal`,
  `data-stagger`, `data-counter`, `data-draw` и другими) и оборачивается в `<MotionRoot variant=...>`; сцены
  грузятся отдельным чанком. Блоки `/fsp` управляют анимацией сами через `useMotion`.
- **Первый экран не мигает.** `MotionFlag` ставит класс `motion` на `<html>` во время разбора HTML. Только при этом
  классе и только на десктопе CSS скрывает блоки `[data-hero]` до появления; через 3,5 с их показывает CSS-страховка
  на случай сбоя скрипта.
- **`prefers-reduced-motion: reduce`.** Не запускаются ни GSAP, ни Lenis, граф рисует один статичный кадр,
  горизонтальные пины становятся обычной прокруткой, CSS-анимации обнуляются правилом в `globals.css`.
