# web — фронтенд «ФСП Таланты»

Next.js 16 (App Router) + TypeScript strict, Tailwind CSS 4, TanStack Query, react-hook-form + zod, lucide-react,
GSAP + Lenis для анимаций публичного сайта. Node.js ≥ 20.9.

## Страницы

**Публичный сайт** (`src/app/(public)`, серверный рендеринг; шапка, подвал и Lenis — в общем layout):

| Путь | Что там |
|---|---|
| `/` | Главная: первый экран с карточкой приглашения и графом-канвасом, бегущая строка из 18 категорий, история «вакансия → приглашение» на ноутбуке и телефоне, диалог соискателя и компании, выбор «я ищу работу / я нанимаю» |
| `/seekers` | Соискателям: уведомление о приглашении на экране блокировки, первая неделя по дням, мини-демо адаптивного теста, свайп приглашений, приватность, что подготовить |
| `/business` | Компаниям: разбор текста вакансии, сравнение «до и после», тур по кабинету, правила для всех компаний, первая потребность |
| `/fsp` | Участникам ФСП: привязка ФСП ID, разряды, дисциплины, сезон соревнований |
| `/vacancies`, `/vacancies/[id]` | Опубликованные вакансии с фильтрами и карточка вакансии |
| `/privacy` | Политика обработки ПДн; действующие тексты согласий запрашиваются у API на сервере при каждом запросе |
| `/guardian/confirm?token=…` | Страница законного представителя соискателя 14–17 лет: подтвердить, отказаться, отозвать (noindex) |

`/vacancies` пересобирается раз в минуту (ISR) с первой страницей вакансий в HTML, `/vacancies/[id]` рендерится на
сервере с вакансией внутри (неизвестный id — настоящий 404). Браузер стартует с этими данными (`initialData`) и дальше
работает через API. Пока собирается образ, API недоступен: та сборка `/vacancies` без списка, его загрузит браузер.

**Состояния** (`src/components/states`): `app/not-found.tsx` — 404 в стиле первого экрана (код, объяснение, главные
разделы сайта); `app/error.tsx` — ошибка вне кабинетов с кнопкой «Попробовать снова» (`retry`) и кодом для поддержки
(`digest`); в кабинетах свои `error.tsx` и `loading.tsx` — оболочка и меню остаются, заменяется только раздел.

**Вход** (`src/app/(auth)`): `/login` (с кнопками демо-входа), `/register` (роль, возраст, представитель для 14–17,
согласия), `/verify-email`.

**Кабинет соискателя** (`/candidate/*`, клиентские страницы): главная (одна кнопка следующего шага по состоянию —
заполнить профиль → пройти опрос и тест → ответить на приглашения, открыть показ профиля или смотреть вакансии;
категория, приглашения, спрос, ФСП), профиль и резюме, опрос (шаги с прогрессом и сводкой ответов; грейд для теста
спрашивается здесь один раз), тестирование (грейд из опроса уже выбран, «Изменить грейд» раскрывает выбор; шаг
видеозаписи `/assessment/start`, сессия `/assessment/[id]`), приглашения (вкладки по статусам с сервера, «Показать
ещё»), вакансии и отклики, регулярные задания, настройки с оглавлением разделов (статус
поиска, видимость, ФСП ID, согласия, «Кто открывал ваши контакты», выгрузка данных, удаление аккаунта). Для 14–17 лет
без согласия представителя — баннер в шапке кабинета.

**Кабинет компании** (`/employer/*`): главная (квота, воронка, причины отказов), потребности и подборки
(создание из текста, подборка с объяснениями, категории, план теста), поиск по базе (на телефоне фильтры свёрнуты за
кнопкой «N фильтров»: `aria-expanded`, Esc закрывает и возвращает фокус на кнопку), профиль кандидата, приглашения,
вакансии и отклики, регулярные задания, интеграции (вебхук, ключи API, журнал доставок с фильтром), компания, доверие
и квота. Растущие списки — приглашения, отклики, ответы на задания, журнал доставок — грузятся страницами по курсору
кнопкой «Показать ещё» (`components/ui/LoadMore`: число показанного — в `aria-live`, после последней страницы фокус
переходит на «Показаны все»). Форма новой вакансии отправляет один `Idempotency-Key` на всё время жизни формы.

Длинные формы (вакансия, потребность) устроены одинаково: пронумерованные разделы, справа — предпросмотр или сводка
с готовностью, внизу — плавающая панель действий `FormActions`. Ошибки показываются у поля (`aria-describedby`,
`role="alert"`) сразу после первой попытки отправки и пропадают по мере исправления; `focusFirstError` переводит
фокус к первому полю с ошибкой, а панель перечисляет, что осталось проверить.

**Кабинет модератора** (`/admin/*`, роль `admin`, не индексируется): обзор со счётчиками, прокторинг (очередь тестов
с фильтрами и карточка теста: ответы по сложности, лента событий, запись, решение с комментарием), антифейк и жалобы
(очередь по компаниям и действия), журнал аудита (фильтр по коду кандидата «K-XXXXXX» или id). API — `src/api/admin.ts`; в мок-режиме кабинет недоступен.

```sh

npm run lint       # eslint
```

## Мок-режим

`NEXT_PUBLIC_USE_MOCKS=1` в `.env.local`. Каждая функция `src/api/endpoints.ts` тогда уходит в `src/mocks/handlers.ts`
(модуль загружается лениво): состояние живёт в `localStorage` браузера, поэтому сквозные сценарии работают целиком —
регистрация → подтверждение email («демо-почта» на экране) → профиль → опрос → адаптивный тест (IRT/EAP,
задания генерируются шаблонами) → категория; работодатель видит нового кандидата, приглашает,
кандидат принимает — у работодателя открываются контакты.

- Демо-аккаунты: `candidate@demo.fsp` и `employer@demo.fsp`, пароль `demo12345` (кнопки на странице входа) —
  совпадают с сидом бэкенда.
- ФСП ID в демо: `FSP-000001`, `FSP-000003`, `FSP-000006`, `FSP-000010` (без достижений) — те же, что в `crates/fsp-mock`;
  `FSP-000002` уже привязан к демо-кандидату. Ввод номера вручную — только в мок-режиме, с настоящим API кнопка
  ведёт в ФСП ID (`/api/v1/fsp/link/start`).
- «Сбросить демо-данные» — в боковой панели кабинета (только в мок-режиме).
- Тест в моках короче боевого: 6–12 заданий вместо 8–20. Вместо PDF-профиля открывается страница для печати
  `/candidate/profile/print`.

## Доступность

Цель — 100 в Lighthouse Accessibility на публичных страницах и ноль нарушений axe в кабинетах.

- **Контраст через токены.** Серые `ink-subtle`, `ink-faint`, `night-faint` подобраны так, что текст ими проходит
  WCAG AA (4,5:1) на всех фонах, где используется. Кольцо фокуса на тёмных фонах светлое (`primary-300`).
- **Ссылки в тексте** — утилита `link-inline`: цвет плюс подчёркивание (одного цвета мало, WCAG 1.4.1).
- **Анимации не прячут контент.** Появления меняют `opacity`, а не `visibility`: текст ниже первого экрана остаётся в
  дереве доступности и в порядке табуляции. SplitText не вешает `aria-label` на абзацы: у разбитого на буквы текста
  есть доступная копия (`sr-only` или контурный слой), а сам он `aria-hidden`. Декоративные макеты, где текст
  намеренно полупрозрачный, — `aria-hidden` и `inert`.
- **Кабинеты:** шапка — `header` с хлебными крошками в `nav`, мобильное меню — нативный `<dialog>` (ловушка фокуса,
  Esc, возврат фокуса), заголовок вкладки браузера — «Раздел · Кабинет · ФСП Таланты», у вкладок `Tabs` всегда есть
  панель, тосты объявляются через `aria-live`.

## SEO и ИИ-поиск

- `app/robots.txt/route.ts` — разрешены публичные страницы для поисковиков и ИИ-краулеров (Googlebot, YandexBot,
  GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot и др., все названы явно), закрыты кабинеты, `/admin`, `/guardian`,
  `/login`, `/register`, `/api/`; `Clean-param` для utm-меток (Яндекс); ссылка на sitemap.
- `app/sitemap.ts` — публичные страницы из `PUBLIC_PAGES` и опубликованные вакансии (до 100, рендерится по запросу).
- Метаданные каждой публичной страницы — `pageMetadata(PUBLIC_PAGES.…)`: title, description, canonical, Open Graph
  и Twitter. Кабинеты и `/verify-email` — `noindex`.
- `opengraph-image.tsx` у каждой публичной страницы (и у вакансии — с названием, компанией и вилкой); общий макет в
  `src/lib/og.tsx`. Satori не читает WOFF2 и вариативные шрифты, поэтому Onest (400, 600) и JetBrains Mono (500)
  лежат статическими TTF в `assets/og` (OFL; для вакансий они попадают в standalone через
  `outputFileTracingIncludes`). Twitter-карточка берёт ту же картинку.
- `app/manifest.ts`, `app/favicon.ico` (16/32/48), `app/apple-icon.png` (180), `public/icons/` (192, 512, maskable
  512) — растр из `public/brand/fsp-mark.svg`; `app/icon.svg` остаётся для современных браузеров.
- **JSON-LD** (`src/lib/jsonld.ts`, рендерится на сервере): Organization и WebSite на всех публичных страницах,
  BreadcrumbList на внутренних, ItemList на `/vacancies`, JobPosting на каждой вакансии (вилка в RUB за месяц,
  `TELECOMMUTE` для удалёнки, город — для офиса и гибрида, `directApply`). Тип занятости не размечается: у вакансий
  есть формат работы, но нет полной или частичной занятости.
- **`/llms.txt`** (по llmstxt.org) — что это за платформа, главные правила и ссылки на страницы из `PUBLIC_PAGES`.
  **`/llms-full.txt`** — факты о продукте (тест, подбор, приватность, ФСП, ATS, антифейк, результаты валидации)
  плюс текст всех публичных страниц, извлечённый из их собственного HTML (`src/lib/html-text.ts`), и список
  опубликованных вакансий. Страницы запрашиваются у этого же процесса по `127.0.0.1:$PORT`, результат кешируется
  на 10 минут — текст не расходится с сайтом.
- `scripts/seo-check.mjs` (`npm run check:seo [адрес]`) запрашивает сайт как GPTBot без JavaScript и проверяет
  robots, sitemap, llms-файлы, один `h1`, `lang`, canonical, `<main>` и формы JSON-LD на каждой странице.

## Анимации

Анимации — только на публичном сайте. Разметка без JS полностью читаема, первый экран от анимаций не зависит.

```
src/components/motion/config.ts          профили: MOTION_OK, MOTION_DESKTOP, MOTION_MOBILE, FINE_POINTER
src/components/motion/lazy.ts            ленивая загрузка GSAP и хук useMotion
src/components/motion/gsap.ts            «набор»: GSAP + ScrollTrigger, SplitText, DrawSVG, ScrambleText
src/components/motion/extras/*           плагины отдельных блоков: Draggable + Inertia, Flip, MorphSVG, MotionPath
src/components/motion/MotionRoot.tsx     декларативные анимации серверных страниц по data-атрибутам
src/components/motion/MotionRoot.motion.ts  сами сцены MotionRoot, отдельный чанк
src/components/motion/MotionFlag.tsx     инлайн-скрипт в <head>: класс motion на <html> до первой отрисовки
src/components/motion/SmoothScroll.tsx   Lenis, синхронизированный с ScrollTrigger через gsap.ticker
src/components/motion/core.ts            обычный (не ленивый) GSAP — только для объяснения балла в кабинетах
src/components/site/HeroGraphLazy.tsx    граф-канвас первого экрана, загружается после гидратации
```

**Ленивый GSAP.** `useMotion` (обёртка над идеей `useGSAP`) загружает `gsap.ts` отдельным чанком после гидратации,
а плагины конкретного блока (`extra`) — рядом, только на тех страницах, где они нужны. Компоненты активируются по
одному за задачу (`setTimeout(0)`), первыми — герой и шапка (`urgent`), поэтому на телефоне после гидратации нет
одной длинной задачи. Всё созданное живёт в `gsap.context` компонента и откатывается при размонтировании.

**Два профиля.** Выбираются медиазапросами из `config.ts`:

| | Десктоп: мышь и ширина ≥ 1024 px | Телефоны и планшеты |
|---|---|---|
| Заголовки | SplitText: строки, слова или буквы в зависимости от варианта | Появляются целиком |
| Появления | Вариант страницы: `rise`, `wipe`, `center`, `blur` (сдвиг, clip-path, размытие) | Одно для всех страниц: подъём на 24 px и проявление, только transform и opacity |
| Пины и scrub | Есть: история на главной, тур по кабинету, дисциплины и сезон ФСП | Нет: вертикальные списки, нативные snap-ленты, одноразовые проигрывания |
| Параллакс, наклон от скорости прокрутки | Есть | Нет |
| Плавный скролл | Lenis | Нативный, Lenis не загружается |
| Граф-канвас | До 96 узлов, импульсы по рёбрам, реакция на курсор, работает только в зоне видимости | Редкий граф, один статичный кадр |

Счётчики, рисование SVG и полосы работают в обоих профилях; «магнит» и наклон карточек — при точном указателе
любой ширины (`FINE_POINTER`).

**MotionRoot.** Серверная страница размечает элементы атрибутами и оборачивается в `<MotionRoot variant=…>`:
`data-hero` (появление при загрузке; `data-hero="lead"` никогда не скрывается), `data-split` (`="hero"` — при
загрузке, `data-delay`), `data-reveal` (или с видом: `up`, `left`, `right`, `scale`, `fade`, `wipe`, `center`, `blur`),
`data-stagger`, `data-counter` (+ `data-decimals`), `data-scramble`, `data-draw`, `data-grow`, `data-parallax`,
`data-skew`, `data-magnetic`, `data-tilt`. Сейчас `rise` у главной, `/seekers`, `/business` и подвала, `wipe` —
у `/vacancies`; `center` и `blur` определены, но не используются. Блоки `/fsp` управляют анимацией сами через `useMotion`.

**Первый экран не мигает.** `MotionFlag` ставит класс `motion` на `<html>` во время разбора HTML. Только при этом
классе и только на десктопе CSS скрывает блоки `[data-hero]` до появления; через 3,5 с их показывает CSS-страховка
на случай сбоя скрипта. На телефонах первый экран рисуется сразу.

**`prefers-reduced-motion: reduce`.** Не запускаются ни GSAP-анимации, ни Lenis, граф рисует один статичный кадр,
горизонтальные пины превращаются в обычную прокрутку, CSS-анимации и переходы обнуляются глобальным правилом
в `globals.css`.

плагины, но это не OSI-лицензия — исключение из правила MIT/Apache/BSD согласовано отдельно).

## Типы API

Типы берутся только из OpenAPI бэкенда. После изменения DTO в `crates/api`:

```sh
make gen-api          # из корня: cargo run -p api -- openapi > web/openapi.json + openapi-typescript
npm run typecheck     # компилятор покажет, какие страницы и моки нужно поправить
```

Мок-API (`src/mocks`) типизирован теми же схемами, поэтому расхождение с бэкендом ловится на `tsc`.
Запросы идут через `http()` в `src/api/client.ts` — своя обёртка над `fetch` (обновление сессии при 401,
problem+json → `ApiError`); типы ответов берутся из сгенерированной схемы.
