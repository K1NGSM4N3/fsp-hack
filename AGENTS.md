# AGENTS.md - правила для разработчиков и ИИ-агентов

Хакатон ЛЦТ 2026, спецтрек ФСП: платформа подбора ИТ-специалистов, где работодатель сам выходит
на кандидата из подтверждённой тестом категории. Перед работой прочитай:

| Файл | Что там |
|---|---|
| `docs/ТЗ.pdf` | Техническое задание организаторов; покрытие требований - `docs/solution.md`, раздел 1.2 |
| `docs/architecture.md` | Зафиксированные решения: стек, механики тестирования и подбора, ФСП, безопасность, схема данных |
| `docs/api.md` | Соглашения API и правила, которых нет в OpenAPI; методы - в Swagger (`/api/docs`) |
| `README.md` | Что это и как запустить: сервисы, порты, профили compose, демо-аккаунты |
| `docs/solution.md` | Описание решения для жюри; из него `make docs` собирает PDF и DOCX |
| `web/README.md` | Фронтенд: страницы, устройство, анимации, переменные окружения |

`docs/architecture.md`, `docs/api.md` и этот файл - рабочие, живут до финальной сдачи.

## Структура

```
crates/catalog     справочники: специализации, грейды, категории, отрасли
crates/assessment  чистая логика тестирования: IRT, CAT, шаблоны заданий, политика грейда
crates/matching    чистая логика подбора: навыки, ФСП-скор, скоринг, разбор резюме
crates/db          доступ к PostgreSQL на sqlx: запросы с проверкой при компиляции, миграции
crates/api         axum-сервер: HTTP, auth, OpenAPI, сервисы
crates/fsp-mock    заглушка реестра ФСП
crates/ats-mock    демо-ATS работодателя: подписанные вебхуки, этапы найма обратно
crates/embedder    локальная модель эмбеддингов текстов (candle, multilingual-e5-small), POST /embed
crates/validate    симуляция и отчёт валидации
db/migrations      миграции sqlx: NNNN_name.sql
.sqlx/             метаданные запросов для офлайн-сборки (make db-prepare)
web/               Next.js
deploy/            compose, Dockerfile'ы, Caddy, Keycloak, Grafana; compose.blackbox.yml - стек для black-box тестов
tests/blackbox/    black-box тесты: Playwright + TypeScript, свой package.json
```

## Команды

```sh
make db          # создать локальную БД fsp_hack (нужен запущенный Postgres)
make db-prepare  # применить миграции к DATABASE_URL и обновить .sqlx/
make api         # запустить API на :8000 (миграции при старте; демо-данные - SEED_DEMO=true make api)
make fsp-mock    # заглушка реестра ФСП на :8090
make ats-mock    # демо-ATS на :8082
make model       # скачать веса модели эмбеддингов в models/ (ревизия и sha256 закреплены)
make embedder    # сервис эмбеддингов на :8093
make gen-api     # выгрузить OpenAPI в web/openapi.json и сгенерировать TS-типы
make web         # Next.js dev-сервер на :3000
make test        # модульные тесты (cargo test --workspace, без БД и сети) + проверка типов web
make blackbox    # чистый стек (свои тома) -> Playwright по публичным портам; DOWN=1 - снести стек после, ARGS=... - аргументы playwright
make blackbox-degraded # после make blackbox: остановить эмбеддер и проверить, что всё работает на ключевых словах
make blackbox-down # остановить стек black-box тестов и удалить его тома
make lint        # cargo fmt --check, clippy -D warnings, eslint
make validate    # прогнать валидацию -> docs/validation/
make docs        # docs/solution.md -> docs/solution.pdf и docs/solution.docx (pandoc + typst)
make up          # docker compose --profile full up -d --build
make down        # остановить стек
make logs        # логи api
```

## Правила

### Общие
- Стек зафиксирован в `docs/architecture.md`, раздел 2. **Не добавлять**: Vite, SurrealDB, OLAP, Redis (только Valkey). Новая зависимость - только если без неё никак; лицензия MIT/Apache-2.0/BSD/ISC/MPL. Согласованное исключение - GSAP (бесплатная Standard License) для анимаций публичного сайта.
- Код, идентификаторы и комментарии в коде - на английском. UI, документация, сообщения об ошибках для пользователя - на русском.
- Закрыл требование - отрази это в таблице покрытия ТЗ (`docs/solution.md`, раздел 1.2). Добавил или изменил эндпоинт - опиши его в `#[utoipa::path]`; правило, которого не видно из схем (лимит, срок, побочный эффект), - в `docs/api.md`. Изменил решение - обнови `docs/architecture.md`.
- Секреты только через env (`.env` не коммитим, шаблон - `.env.example`).

### Обязательные правила кода
- **Без мусорных комментариев.** Никаких комментариев, пересказывающих код, и разделителей-баннеров. Комментарий - только "почему", и только там, где решение неочевидно (психометрика, формулы скоринга, криптография).
- **Ошибки - только `thiserror`.** `anyhow` в проекте не используется.
- **Горячие и холодные данные - в разных структурах.** То, что трогается в горячих циклах (скоринг, CAT, поиск), - компактные типы: числовые id вместо строк, `f32`/`u16`/`u8`, где хватает точности, битсеты, массивы структур без `String`. Строки, тексты и объяснения - отдельно и материализуются только для итогового результата.
- **Коллекции по делу.** Пара элементов на холодном пути - `Vec`/массив, а не map. Внутренние закрытые наборы ключей (id навыков, шаблонов) - `FxHashMap` (`rustc-hash`) или плотный массив по индексу. Ключи от клиента - только std `HashMap` (SipHash, защита от HashDoS) и с ограничением размера. `BTreeMap` - только если реально нужен порядок или диапазонные запросы.
- **Lock-free.** Разделяемое изменяемое состояние - на атомиках, без `Mutex`/`RwLock` в нашем коде. Неизменяемые данные - `LazyLock`/`OnceLock`.

### Rust
- `catalog`, `assessment`, `matching` не знают про HTTP, БД и время: всё, что зависит от "сейчас" или случайности, принимает `now` / `seed` / `Rng` параметром - так код детерминирован и тестируем.
- SQL пишем только в `crates/db` и только макросами `sqlx::query!` / `query_as!` / `query_scalar!`: запрос проверяется по схеме при компиляции. Строковый `sqlx::query()` - нельзя; по-настоящему динамический SQL - через `QueryBuilder`, с комментарием почему. Функции принимают `impl PgExecutor<'_>`, чтобы работать и с пулом, и с транзакцией.
- Сборка идёт офлайн (`SQLX_OFFLINE=true` в `.cargo/config.toml`): изменил запрос или схему - `make db-prepare` и коммить `.sqlx/` вместе с кодом. Схема - только миграциями, существующие миграции не редактируем.
- Единый `ApiError` -> problem+json в `api`. Никаких `unwrap()`/`expect()` в путях обработки запросов.
- Каждый хендлер описан в utoipa (`#[utoipa::path]`) с кодами ошибок - иначе его нет в Swagger.
- Правила видимости - в типах: DTO работодателя не содержит контактов; `CandidateContacts` строится только из `ContactGrant`.
- Перед коммитом: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `make test`; задел интерфейс или сценарий - `make blackbox`.

### Тесты
Тестов два вида, и только они. Интеграционных тестов "изнутри" (поднять `AppState` в процессе, писать в базу, подменять триггерами) в проекте нет.

- **Модульные** - `#[cfg(test)] mod tests` рядом с кодом в `crates/*/src` и `crates/matching/tests/` (только публичный API крейта). Запуск - `make test`.
  - Можно: чистые функции, типы, сериализация, рендер писем, axum-ответы без сети (`into_response`, `oneshot`), `Crypto::new` с фиксированными ключами.
  - Нельзя: БД, сеть, Valkey, файлы вне временного каталога. Результат не зависит от часов и случайности: `now`, `seed`, `Rng` передаются параметром. `make test` проходит без Postgres.
  - Логика, которую хочется проверить, но она сидит внутри хендлера рядом с запросами в БД, выносится в чистую функцию рядом (`plan`, `check_outcome`, `visibility_gate`...) и тестируется там; хендлер только собирает факты из базы и вызывает её.
- **Black-box** - `tests/blackbox/` (Playwright Test, TypeScript strict). Запуск - `make blackbox`: поднимает отдельный compose-проект `fsp-hack-blackbox` (`deploy/compose.yml` + `deploy/compose.blackbox.yml`) на тех же портах с чистыми томами и детерминированным демо-сидом, останавливает при этом стек `make up` (его тома остаются), ждёт готовности и гоняет тесты. Отчёт - `tests/blackbox/playwright-report/`.
  - Можно: веб-интерфейс и HTTP API через :8080, Mailpit (:8025) как почтовый ящик пользователей, демо-ATS (:8082) и админку заглушки реестра ФСП (:8091) как внешние системы, демо-данные из README, новые аккаунты через публичную регистрацию с подтверждением из письма. Настраивать стек можно только переменными окружения в `compose.blackbox.yml` (сейчас - короткие паузы писем).
  - Нельзя: SQL, `docker exec`, логи контейнеров, внутренние бинарники, очистка Valkey, импорт Rust-крейтов, знание правильных ответов теста.
  - Каждый spec независим и запускается параллельно с другими; общие засеянные ресурсы (очередь модерации) - в одном файле с `test.describe.configure({ mode: "serial" })`. Свой засеянный соискатель и своя компания на spec - `tests/blackbox/lib/accounts.ts`. Ожидание - условием (`expect.poll`, `toPass`, ожидание локатора), без фиксированных пауз.
  - Вход ограничен 10 попытками за 15 минут на IP + email: сессии демо-аккаунтов хранятся в `tests/blackbox/.auth/` по одной на слот воркера (фикстура `login`), setup-проект логинит их заранее.
- Добавил поведение - добавь модульный тест на логику и, если поведение видно снаружи, сценарий в black-box. Что не покрыто ни тем ни другим и почему - `docs/architecture.md`, раздел 14.

### Frontend
- Next.js App Router, TypeScript strict. Кабинеты - клиентские компоненты с TanStack Query; серверный рендеринг - только для публичных страниц.
- API - только через сгенерированный клиент (`web/src/api`), руками типы ответов не описываем.
- Права проверяет бэкенд. Proxy Next (`web/src/proxy.ts`, бывший middleware) - только редирект на логин.
- Цвета и шрифты ФСП - токены в `web/src/app/globals.css`; новых цветов мимо токенов не вводим.
- Вёрстка адаптивная, проверяем на ширине 375 px.

### Git

- Сгенерированное (`.sqlx/`, `web/openapi.json`, `web/src/api/schema.d.ts`) коммитим вместе с источником.
